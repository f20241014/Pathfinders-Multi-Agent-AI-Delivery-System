What the numbers show: how often A* calls the heuristic, how long one call and one edge-cost lookup take on this machine, and how A*'s mean run time changes when each heuristic call becomes a dictionary lookup (same pairs, same expansions, same costs). Precomputing the table is not included in that time; it is not a fair way to run A* for one trip, only a way to remove the heuristic's cost from the measurement.

What they do not prove: they are means of single runs on the one machine named above (OS and Python version) and would differ on other machines or Python versions; they do not show how the rest of A*'s time is split (heap operations, dictionary updates); and a faster heuristic implementation was not tried.
